## Соглашения

- **MUST** — обязательно. **SHOULD** — предпочтительно, отклонение нужно записать с обоснованием. **MAY** — допустимо.
- **VERIFY** — утверждение о сторонней системе (ContextForge, FastMCP, провайдер). Его нужно подтвердить тестом на закреплённой версии, прежде чем на него опираться.
- Требования имеют идентификаторы (`SEC-03`, `EFF-05`, `MCC-07`). Тесты в [Conformance Matrix](conformance-matrix-v1.md) ссылаются на них.
- Текст на русском. Идентификаторы, коды ошибок, статусы и поля — на английском.

## Глоссарий

- **Tenant** — изолированный клиент Hub (мы сами или клиент). В ContextForge — team. Данные, credentials и политики одного tenant недоступны другому.
- **Principal** — аутентифицированный субъект: агент (machine principal) или человек (human principal). Имеет неизменяемый ID от identity-провайдера.
- **Capability / tool** — MCP-инструмент, опубликованный через ContextForge.
- **Коннектор** — самостоятельный MCP-сервер для одного домена (KB, Telegram, CRM), работающий поверх существующего backend.
- **Effect** — действие с последствиями вне чтения: отправка, публикация, запись.
- **Intent** — неизменяемая заявка на конкретный эффект с точными параметрами.
- **Approval Service** — наш сервис, который хранит intents, решения людей и управляет исполнением.
- **Effect Executor** — часть Approval Service, единственный, кто может вызвать исполнение эффекта в коннекторе.
- **Execution token** — подписанный короткоживущий одноразовый токен, разрешающий коннектору исполнить ровно один intent.
- **Provider** — внешняя система (Telegram API, CRM, соцсеть).
