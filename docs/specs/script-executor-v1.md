# Исполнитель скриптов v1

**Статус:** спека для будущей вехи, в текущие вехи не входит (решение владельца 2026-11-26, [ADR-0007](../adr/0007-layer-boundaries-and-script-executor.md)). Числа с пометкой *default* — мои значения по умолчанию, ждут подтверждения владельца. Составлено 2026-11-27.

## Зачем

Сценарий вроде «собрать участников десятков чатов» — цикл на сотни вызовов. Агент в диалоге делает его по одному вызову и тратит контекст. Скрипт делает цикл сам и возвращает короткий итог. Исполнитель не добавляет прав: каждый вызов идёт тем же путём, что и вызов агента.

## Границы

- Исполнитель — клиент Hub, наравне с агентом и Signals. Он не часть ContextForge и не хранит определений tools.
- Он отдельный контейнер и отдельная сеть, поставляется вместе с Hub (один compose).
- Расписаний и прогресса источников в нём нет: это Signals. Исполнитель делает один запуск и возвращает результат.

## Требования

- **SX-01. Вход.** Агент вызывает один MCP-tool `hub.script.run` с аргументом `script` (текст, ≤ 32 KiB *default*). Tool зарегистрирован в ContextForge штатно, имя не содержит `execute`, `reconcile`, `propose` (EFF-02). Если для регистрации нужна доработка ContextForge, фасада нет, агент подключает исполнителя как отдельный MCP-сервер.
- **SX-02. Мост.** Скрипту доступна одна функция `call(tool, args)`. Она отправляет запрос в ContextForge с identity того агента, который запустил скрипт, под теми же `unified_pdp`, grants, квотами и аудитом. Своих учётных данных у исполнителя для провайдеров нет.
- **SX-03. Что можно вызывать.** Только tools `read` и `propose`, включая `ext.search/describe/call` для записей класса `read`. Исполнять эффект скрипт не может (EFF-02, SEC-20, SEC-21 как для агента). Вызов `*.execute` и `reconcile` отклоняется на мосту до ContextForge.
- **SX-04. Права не расширяются.** У скрипта ровно те права, что у запустившего агента в момент вызова. Отозванный токен или сработавший kill switch останавливает скрипт на следующем вызове моста.
- **SX-05. Песочница.** Нет сети, кроме моста; нет переменных окружения и секретов; нет файловой системы, кроме временной в памяти. Лимиты на запуск *default*: 60 с по времени, 256 MiB памяти, 500 вызовов моста, 1 MiB результата. Превышение — запуск прекращается кодом `limit_exceeded` с названием лимита.
- **SX-06. Результат.** Скрипт возвращает один JSON-результат. Данные из ответов tools остаются данными: инструкции в них не меняют права и не запускают вызовы (как SC-08).
- **SX-07. Эффекты через propose.** Если скрипт вызывает `propose`, intent создаётся как у агента и ждёт решения человека. В результат запуска попадают id intent'ов, не решения.
- **SX-08. Аудит.** Запись запуска: tenant, principal агента, хэш скрипта (SHA-256), число вызовов моста, длительность, итог. Тела скрипта и значений данных в аудите нет. Каждый вызов моста пишется в аудит ContextForge как обычный вызов агента.
- **SX-09. Данные `pii`.** Значения из групп `pii` (SEC-23) не попадают в лог исполнителя и в аудит запуска. В результат они попадают только если у агента есть право и скрипт их вернул явно.
- **SX-10. Ошибки.** Коды: `limit_exceeded`, `script_error` (исключение скрипта, с типом без значений), `permission_denied` (вызов не из `read`/`propose`), `unavailable`. Ошибка вызова моста возвращается скрипту как данные MCC-05, а не обрывает запуск, пока скрипт сам не завершится.
- **SX-11. Первый поддерживаемый язык.** Один: тот, что выберет реализация. В спеке язык не фиксируется; песочница должна давать SX-05 независимо от языка.

## Критерии приёмки (для будущей вехи)

| ID | Критерий |
| --- | --- |
| AC-SX-01 | `hub.script.run` регистрируется в ContextForge без доработок; вызов агентом проходит с правилами `deny:agents-never-execute` как есть |
| AC-SX-02 | Скрипт, вызывающий чат вне прав агента, получает `not_found` как агент; счётчик обращений к транспорту Telegram = 0 |
| AC-SX-03 | Вызов `*.execute` или `reconcile` из скрипта → `permission_denied` на мосту, до ContextForge ничего не доходит |
| AC-SX-04 | Скрипт без сети и секретов: попытка открыть сокет и прочитать переменные окружения даёт ошибку; тест с известными значениями секретов находит 0 вхождений в выходе |
| AC-SX-05 | Каждый лимит SX-05 срабатывает отдельным тестом с `limit_exceeded` и именем лимита; процесс и память после запуска освобождены |
| AC-SX-06 | Отзыв токена агента во время запуска → следующий вызов моста отклонён ≤ 1 мин, запуск завершается ошибкой |
| AC-SX-07 | Аудит запуска содержит хэш и число вызовов; 1000 запусков с известным телефоном и текстом сообщений: 0 вхождений в логи и аудит |
| AC-SX-08 | Скрипт с `propose` создаёт intent в `pending_approval`; вызов исполнения из скрипта невозможен (SX-03) |
| AC-SX-09 | Сквозной пример: цикл по N чатам с `participants.collect` по курсору собирает тот же итог, что серия вызовов агента (AC-M11.4-09), и укладывается в лимиты SX-05 |

## Не входит

Хранение скриптов, расписания, права скрипта выше прав агента, исполнение эффектов, внешние библиотеки, сеть. Когда понадобятся — отдельное решение.
