# ADR-0003: сеть и доступ через Tailscale

**Статус:** Accepted — решение владельца, 2026-11-21.

## Контекст

В SEC-13 (до этого решения) ContextForge (MCP) и Approval Web UI открыты в интернет по HTTPS, админка — «с ограниченного интерфейса или VPN». Конкретный VPN не выбран. Пользователи Hub — наши агенты и наши люди (оператор, approver'ы клиентов), анонимных пользователей нет. Публичная точка входа поэтому добавляет только поверхность атаки: сканирование, перебор токенов, эксплуатация уязвимостей ContextForge до аутентификации (см. advisories в SEC-22).

## Решение

Ничего не публикуется в интернет. Все точки входа — только в tailnet Tailscale:

| Точка входа | Тег узла | Кто ходит | Порт |
| --- | --- | --- | --- |
| ContextForge MCP | `tag:gateway` | `tag:agent`, `group:operators` | 443 (`tailscale serve`; `/admin` и admin API закрыты на прокси) |
| Админка ContextForge | `tag:gateway` | `group:operators` | 8443 (отдельный `tailscale serve`) |
| Approval Web UI (`ui`) | `tag:approval-ui` | `group:approvers`, `group:operators` | 443 |
| Approval `admin` | `tag:approval-admin` | `group:operators` | 443 |

Внутренние сервисы (коннекторы, `api`, `mcp`, executor, базы) в tailnet не входят.

- Tailscale — только сетевой слой. Аутентификация и авторизация остаются прежними (SEC-25).
- ACL хранится в Git, применяется через GitOps и покрыта `tests` (SEC-26).
- Funnel, exit node и subnet router на узлах Hub запрещены (SEC-27).
- Egress (провайдеры, IdP, Telegram Bot API) идёт обычным интернетом по allowlist (SEC-15).

## Последствия

- **Плюс:** нет публичной поверхности, перебор и сканирование извне невозможны. Отдельный VPN и WAF не нужны. HTTPS-сертификаты `*.ts.net` выдаёт Tailscale.
- **Минус:** у каждого approver'а должен быть клиент Tailscale на устройстве, где он открывает ссылку из бота. Иначе ссылка `/intents/<id>` не откроется. Устройства подтверждаются администратором tailnet.
- **Минус:** появляется внешняя зависимость — координационный сервер Tailscale. При его недоступности уже установленные соединения работают, новые устройства не подключаются. Компрометация аккаунта Tailscale даёт достижимость, но не полномочия (SEC-25). Админы tailnet = операторы, MFA обязательна.
- **Агенты клиентов**, если появятся вне нашей инфраструктуры, подключаются как `tag:agent` через выданный ключ или sharing узла `tag:gateway`. Отдельное решение — при первом таком клиенте.
- **Локальный dev-стенд** (`compose.yaml`) не меняется: он слушает только `127.0.0.1`.

## Проверка

- OPS-06: снаружи tailnet и между неразрешёнными тегами соединения нет, Funnel выключен, ACL `tests` зелёные.
- OPS-07: внутри tailnet без наших токенов — 401/403.
- Вводится в M14 (hardening). До этого стенды остаются локальными.

## Отклонённые варианты

- **Только операторский доступ через Tailscale**, MCP и Web UI публично: оставляет публичную поверхность без нужды, потому что все пользователи свои.
- **Tailnet + Funnel для Web UI:** Funnel снова делает UI публичным.

## Хостинг (решение владельца 2026-11-22)

Хостинг — Railway (SEC-28):
- у сервисов Hub нет публичных доменов Railway и TCP Proxy;
- внутренние вызовы идут по private networking;
- в контейнерах точек входа работает `tailscaled` в режиме userspace-networking, сертификаты `*.ts.net` выдаёт `tailscale serve`.

Админка ContextForge отдаётся на отдельном порту 8443, доступ к нему есть только у `group:operators`. На порту MCP (443) путь `/admin` закрыт. Причина: ACL Tailscale разграничивает порты, а не пути, и агент с доступом к 443 иначе дотянулся бы до админки.
