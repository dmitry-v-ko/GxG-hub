# ADR-0007: Границы слоёв и исполнитель скриптов (code mode)

**Статус:** Proposed — решение владельца 2026-11-26 по сути принято (вариант «Б по архитектуре, А по развёртыванию»), текст ждёт просмотра. Уточняет [ADR-0005](0005-telegram-service-mcp.md).

## Слои

- **Источник (коннектор-сервис)**, например `gxg-telegram-service`. Ядро: чьи ресурсы, права на ресурс, реестр возможностей, политика лимитов. Выходной порт — транспорт к провайдеру (для Telegram адаптер на Pyrofork), там живут все методы провайдера. Входной адаптер — MCP-поверхность: tools ядра, `<domain>.ext.search/describe/call`, `*.propose`. Определения tools и реестр принадлежат сервису.
- **Hub (ContextForge, ADR-0002)** — шлюз: RBAC, `unified_pdp`, grants, identity, аудит, согласование. Определений tools не хранит и расписаний не знает.
- **Signals (`gxg_agents_v2`)** — свой гексагон: источники, расписание, прогресс, карточки. Ходит в Hub через порты `CollectSource` и `ExecuteAction`.
- **Исполнитель скриптов** — клиент Hub, наравне с агентом и Signals. Не часть шлюза.

## Куда класть новую функцию провайдера

| Признак | Куда |
| --- | --- |
| Любая операция провайдера | метод транспорта + запись реестра |
| Частая, типизированная, с полными тестами | tool ядра |
| Редкая, только чтение | запись `ext.*` (класс `read`) |
| Эффект | `propose`-tool, не раньше этапа E |
| Смысл бизнеса (следить, оценивать) | Signals |

## Исполнитель скриптов

**Решение.** Исполнитель — отдельный компонент, а не код внутри ContextForge. Скрипт ходит в инструменты через мост `call(tool, args)` обычным путём: через ContextForge, с identity агента, под теми же `unified_pdp`, grants, квотами и аудитом. Обхода проверок нет по построению.

**Условия (обязательные).**
1. **Отдельный контейнер и сеть.** Поставка и релиз вместе с Hub (один compose) допустимы; один процесс или общий контейнер с ContextForge недопустимы.
2. **Фасад `hub.script.run` только как обычный MCP-tool**, зарегистрированный в ContextForge штатно. Если для него нужна доработка ContextForge, фасада нет: агент обращается к исполнителю как к отдельному MCP-серверу. Имя не содержит `execute`, `reconcile` и `propose`: запрет EFF-02 (`deny:agents-never-execute`, `tools.invoke.*execute*`) не ослабляется (решение владельца 2026-11-26: переименовать; прежнее имя `hub.execute` попадало под этот запрет, [M11-cf-stand](../../reports/M11-cf-stand.md), проверка 6).
3. Песочница: нет сети, кроме моста; нет секретов; лимиты времени, памяти, числа вызовов и размера результата; хэш скрипта и число вызовов в аудите.
4. Скрипт может вызывать `read` и `propose`; исполнять эффект он не может (SEC-20, SEC-21 действуют как для агента).
5. Простые команды для скриптов — тонкий SDK, генерируемый из `ext.search/describe` и каталога tools. Источник правды остаётся в реестре сервиса.

**Цена решения.** Мост идёт через сеть и ContextForge на каждый внутренний вызов (медленнее локального моста); релизы Hub и исполнителя связаны.

## Не сейчас

Исполнитель не входит в текущие вехи. Он начинается, когда у агента становится ~30–50 tools или когда сценарий требует цикла по сотням вызовов (первый кандидат — сбор участников, M11.4/M12.1). Контракт исполнителя — [script-executor-v1](../specs/script-executor-v1.md).
