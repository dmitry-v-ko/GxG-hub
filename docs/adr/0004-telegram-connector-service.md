# ADR-0004: Telegram-коннектор — отдельный сервис со стандартным контрактом

**Статус:** Accepted — решение владельца, 2026-11-21. Детали реализации выбраны оркестратором по поручению владельца («реши сам, чтобы не застопорить работу»).

## Контекст

Сессией Telegram, блокировками, archive-sync, flood-wait и секретами владеет существующий Telegram-сервис в `gxg_agents_v2`. Второго владельца сессии быть не должно. Сетевого порта для чтения архива у этого сервиса нет. Поиск (`PostgresTelegramArchiveRepository.search`) вызывается только в процессе Mastra, чтения ветки и сбора по чату нет (M11, цикл 1).

## Решение

Telegram-коннектор — отдельный сервис: `connectors/telegram` в GxG Hub, свой образ. С Hub он связан только стандартным [MCP Connector Contract](../specs/mcp-connector-contract-v1.md): MCP за ContextForge, `X-GxG-Identity`, grants, канонические ошибки, readiness.

- **Источник данных для чтения.** Коннектор читает архив `telegram_archive`, который наполняет archive-sync существующего сервиса. Подключение — отдельной ролью PostgreSQL только на `SELECT` нужных таблиц, по схеме из миграций `gxg_agents_v2`. Код `gxg_agents_v2` не меняется. Telegram-сессию коннектор не открывает (AC-M11-02 выполняется по построению).
- **Тools.** `telegram.messages.search`, `telegram.thread.read`, `telegram.messages.collect` (курсор по архиву). Live-операции (live fallback, `telegram.message.propose`) требуют сессии, поэтому коннектор их не публикует до отдельного решения, не позже M13. Варианты на тот момент: узкий внутренний порт у владельца сессии или перенос владения сессией в этот сервис.
- **RID чата** — `telegram:<connection>/chat/<chat_ref>`, где `chat_ref` — стабильный ID чата в архиве. Peer ID Telegram наружу не выходит (MCC-04, AC-M11-05).
- **Проверки M11.** Без живого Telegram. Локальный PostgreSQL со схемой архива из миграций `gxg_agents_v2` и синтетическими fixtures, стенд ContextForge из M5. Прогон на реальном тестовом аккаунте не нужен: коннектор с Telegram не говорит.

## Последствия

- Свежесть данных = задержка archive-sync. Для Signals (M12) это приемлемо: сбор по курсору.
- Схема архива становится контрактом между сервисами. Её изменение в `gxg_agents_v2` ломает коннектор. Поэтому нужен контрактный тест схемы в CI коннектора по миграциям `gxg_agents_v2` (закреплённый commit) и уведомление при обновлении.
- Роль БД с доступом на чтение к архиву — секрет коннектора (SEC-16, AS-28 по аналогии). Её доступ проверяется тестом: запись этой ролью отклоняется.
