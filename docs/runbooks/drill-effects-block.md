# Учебная тревога 1: блокировка эффектов за ≤ 5 минут (AC-M14-05)

Сценарий: провайдер или агент ведёт себя неверно (дубли сообщений, неожиданные получатели). Нужно остановить все эффекты. Подробности механизма — [approval-ops §1](approval-ops.md#1-kill-switch-ex-13-as-05). Цель: от сигнала до подтверждённой блокировки **не больше 5 минут**. Время фиксирует ведущий учения по часам, не дежурный.

**Кто.** Дежурный (не автор runbook'а) в роли оператора из `GXG_ADMIN_OPERATORS`; ведущий читает сценарий и ведёт протокол (`reports/drills/`, шаблон `TEMPLATE.md`).

**Подготовка (до старта часов).** Есть доступ к устройству из `group:operators` в tailnet, действующий ID token оператора (`GXG_OPERATOR_TOKEN_FILE`), `GXG_ADMIN_URL` администратора (`tag:approval-admin`). Для учений используется стенд или пилот с тестовым tenant'ом `t-pilot`; ведущий заранее создаёт один intent в `approved`/`pending_approval` (тестовое сообщение), чтобы проверить блокировку.

## Шаги

1. **00:00 — сигнал** ведущего: «агент `t-pilot` шлёт дубли». Часы запущены.
2. **Заблокировать всё глобально** (быстрее, чем искать причину):
   ```bash
   gxg-approval switch set --scope global --reason "DRILL: duplicate messages from agent"
   ```
   Ответ `blocked: true`. Если токен оператора истёк, получить новый вход в IdP (сессия не старше 5 минут нужна только для **снятия**).
3. **Подтвердить блокировку** одним из способов:
   - `GET /v1/switches` в admin API: строка `global` с `blocked: true`;
   - попытка `dispatch` отклоняется кодом **423** (`effect_disabled`), провайдер не вызывается: ведущий создаёт или одобряет тестовый intent и убеждается, что он не ушёл (статус `approved`/`failed`, в журнале провайдера записи нет);
   - метрика `gxg_switch_blocked{scope="global"}` = 1.
4. **00:05 — стоп часов**, если п. 3 выполнен. Записать время в протокол.
5. **Дальше (вне зачёта по времени):** найти причину (журнал `audit_events`, intents за последний час), при необходимости перейти к [отзыву токена агента](drill-agent-token.md).
6. **Снять блокировку** после учения: `gxg-approval switch clear --scope global --reason "DRILL over"`. Нужен свежий вход (`auth_time` не старше 5 минут), иначе 403.

## Критерий и что записывает ведущий

Время от шага 1 до подтверждения (п. 3) ≤ 5 мин; блокировка подтверждена кодом 423 или состоянием switch; после снятия эффекты снова идут (одно тестовое сообщение). В протоколе: имя дежурного, время по шагам, затруднения, правки runbook'а. Протокол заполняет человек.
