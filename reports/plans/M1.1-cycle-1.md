# M1.1 — MCP Toolkit, цикл 1: план

Ветка `claude/m1.1-toolkit` от `origin/claude/integration` (M0…M5, M7, `demo` M3) + свежие `docs/`, `reports/GOAL.md` из `claude/admiring-planck-vzys0x`.
Ponytail `ultra` (первый цикл). Формат — «Что | Зачем | Почему».

## Шаги

- **Что:** вынести обвязку `demo` (Settings, ключи, bundle, verifier, `/healthz`, `/readyz`, конвейер вызова tool'а, envelope, аудит, тайм-аут) в модуль кита `gxg_connector_kit.mcp` (extra `[mcp]`) | **Зачем:** шаблон генерирует 30 строк вместо 450; AC-M1.1-01, -04 | **Почему:** иначе каждый сервис копирует identity/grants/ошибки — те же классы ошибок, что критики находили в M3, M6, M11.
- **Что:** в конвейере кита обязательный hook ресурса по `resource` из manifest: identity → схема → bundle → предпроверка `allowed()` (нет прав на тип — `not_found` без вызова backend) → RID → `check()` → handler получает `Access` | **Зачем:** MCC-02, MCC-03, GR-16, GR-17; «hook, который нельзя пропустить» | **Почему:** handler без `Access` не вызывается, tool без `resource` не регистрируется; иначе проверку прав забывают.
- **Что:** kit проверяет `structuredContent` по output schema и лимиту размера, а `limit.maximum` входной схемы — по `limits.max_results` при старте | **Зачем:** MCC-04 «ограниченный вывод» | **Почему:** иначе испорченная копия с неограниченным выводом проходит.
- **Что:** модуль `gxg_connector_kit.effects`: клиент Approval Service, `propose` → intent, внутренние `execute`/`reconcile` (порядок EFF-18), обобщённый из `demo/effects.py` ветки M8 | **Зачем:** `--with-effects` шаблона; EX-03/04/05/11/14/16 | **Почему:** без него каждый сервис пишет EFF-18 сам; эталон — уже проверенный критиками M8 код.
- **Что:** взять из M8 только kit-часть дословно: `exec_token.sign`/`public_jwk`, схемы `execute-request`, `reconcile-result` в `_schema` | **Зачем:** effects и conformance подписывают execution token | **Почему:** те же hunks, что в M8, — слияние без конфликта; остальное M8 (`demo/effects.py`, тесты M8) не берём — договорённость владельца.
- **Что:** пакет `tools/gxg-connector-check`, CLI `check-connectors --connector <path>`: pytest-набор MC, SC, EX + MCC-05/09 по harness коннектора (`[tool.gxg-connector-check] harness = …`) | **Зачем:** AC-M1.1-02, -03 | **Почему:** общий набор — единственный способ доказать соответствие MCC у сервиса в чужом репозитории.
- **Что:** 10 испорченных копий `demo` (patch + ожидаемая проверка) и 3 копии сгенерированного `sample --with-effects` для EX; тест: каждая краснеет ровно на своей проверке | **Зачем:** AC-M1.1-02 | **Почему:** без этого набор может быть зелёным всегда.
- **Что:** шаблон copier `templates/python-fastmcp/` + `scripts/new-connector --name <domain> --lang python [--with-effects] [--kit-source path|git]` | **Зачем:** AC-M1.1-01, mcp-toolkit-v1 «Что генерирует шаблон» | **Почему:** без генератора новый сервис собирается руками.
- **Что:** e2e-тест: `new-connector --name sample --with-effects` в tmp как отдельный git-репозиторий, кит, check и зависимости — git-зависимостями на закреплённый commit, затем его `scripts/check-all.sh` (ruff, mypy, pytest, `check-connectors`) | **Зачем:** AC-M1.1-01, -03 | **Почему:** только так видно, что сервис из чужого репозитория собирается одной командой без правок.
- **Что:** перевести `demo` на `gxg_connector_kit.mcp` и шаблон (`.copier-answers.yml`); тест: файлы, которыми владеет шаблон, у `demo` совпадают с рендером шаблона | **Зачем:** AC-M1.1-04 | **Почему:** иначе «demo на шаблоне» — утверждение без проверки, и шаблон дрейфует от эталона.
- **Что:** `pytest-timeout` в корень и в шаблон; `scripts/ci/mutmut.sh` получает `MUTMUT_DIRS` (пакеты вехи); check-all прогоняет `check-connectors` на `demo` и тесты набора | **Зачем:** DoD-1 (3-я редакция п.3) | **Почему:** зависший тест иначе висит часами; полный mutmut — только при интеграции.
- **Что:** `reports/conformance/M1.1.json` с `self_check`, затем критик-субагент + ponytail-review | **Зачем:** DoD-3, процесс вехи | **Почему:** без отчёта и критика веха не закрывается.

## Лестница ponytail (DoD-6: готовое прежде своего)

| Часть | Ступень | Что рассмотрено | Почему так |
| --- | --- | --- | --- |
| MCP-сервер | установленная зависимость | FastMCP 4.1.8 (уже в `demo`) | Спека: свой фреймворк не пишем |
| Генератор | известный инструмент | **copier** 9.x и cookiecutter | copier умеет `copier update` по `.copier-answers.yml`: сервисы в чужих репозиториях получают обновления шаблона; cookiecutter — только разовая генерация. `_skip_if_exists` отделяет файлы домена от файлов шаблона |
| Conformance-раннер | установленная зависимость | pytest (+ MCP SDK client, ASGI-транспорт как в тестах M3) | Своего раннера нет: `check-connectors` = `pytest` над пакетом с fixture harness |
| Тайм-ауты тестов | известный инструмент | pytest-timeout | DoD-1 |
| Bundle для набора | уже есть в репозитории — **не подходит** | `gxg-policy build` | `gxg_policy.load` ищет `schemas/` в checkout'е репозитория и не импортируется из git-wheel вне его. Набор собирает bundle сам (~30 строк: JSON + JCS + подпись Ed25519 формата GR-11a), тест сверяет байты с `gxg-policy build` на фикстурах `demo` — `shortcut: дублирует bundle_doc для тестов; убрать, когда gxg-policy начнёт упаковывать схемы` |
| Fake Approval Service в наборе | минимальный код | `approval/` (M7) — нужен PostgreSQL | Набору нужны 3 endpoint'а (`/v1/intents`, `/dispatch`, JWKS) для поведения коннектора, а не Approval Service |
| Испорченные копии | stdlib/git | `git apply` патчей к копии `demo` | 10 патчей по несколько строк вместо 10 копий каталога |
| Execution token, service JWT, canonical, grants | уже в ките | — | Переиспользуются, не пишутся |

## Сознательно не делаем

- TypeScript-шаблон (`--lang ts`): спека — «когда появится первый TS-коннектор с эффектами»; генератор отвечает ошибкой.
- SC-01, SC-06, MC-01 через ContextForge, MC-05: требуют стенда; набор помечает их `not_applicable (stand)`, стенд M5 остаётся.
- Реальные репозитории `gxg-telegram-service`/`gxg-kb-service`: пуш только в эту ветку; AC-M1.1-03 доказывается отдельным git-репозиторием во временном каталоге с git-зависимостью на закреплённый commit.
- Слияние `demo/effects.py` и тестов M8: отложено до интеграции (договорённость владельца). После слияния `demo` M8 переводится на `gxg_connector_kit.effects` или оставляет свой модуль — решение интегратора.
