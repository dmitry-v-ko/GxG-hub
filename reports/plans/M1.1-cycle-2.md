# M1.1 — MCP Toolkit, цикл 2: план

Основа — `required_improvements` критика цикла 1 (`reports/critic/M1.1-cycle-1.json`, 6.0). Ponytail `full`.

## Чек-лист критика

1. **Гейт.** Убрать два лишних `# noqa: PLC0415` в `test_effects.py`. `mutmut.sh` берёт список прогнанных мутантов из `$tmp/all.txt`, а не из `$all` (без второго аргумента это `/dev/null`). Тест `tests/ci` запускает `mutmut.sh` без второго аргумента с заглушками `uv`/`docker` в `PATH`. В конце цикла — `scripts/ci/check-all.sh` целиком, как написан, с выводом в `ci_local`.
2. **`.dockerignore`.** Оба варианта исключают `.env*` на любой глубине, `mutants`, кеши; тест рендера.
3. **`copier update`.** `copier.yml` переезжает в корень репозитория (`_subdirectory: templates/python-fastmcp/template`): copier берёт шаблон только из корня git-репозитория. Вне репозитория генерация идёт из git URL на `kit_rev`, поэтому в ответах есть `_src_path` и `_commit`. E2e-тест: сервис из клона, коммит в шаблоне клона, `copier update` в сервисе переносит изменение файла шаблона и не трогает файл домена.
4. **Положительные контроли.** SC-10: после успешных вызовов читателя `calls() > 0`. MC-03: в `Harness.failures` обязательны `rate_limited`, `temporarily_unavailable`, `crash`. Испорченные копии harness demo: счётчик всегда 0, `failures=("crash",)`.
5. **EX.** Фейковый Approval Service считает все запросы dispatch: повтор токена отклоняется коннектором без второго запроса. EX-03 добавляет токен на ресурс и tenant, которые коннектор не обслуживает (хеш согласован) → 403. Копии `sample`: без jti-кеша, `serves()` всегда True.
6. **Списки.** `Call.hidden`/`missing` разрешены и для list-tools: названный скрытый ресурс — тот же `not_found`, что несуществующий. `Call.empty`: пустой результат — успех. Пагинация: `limit=1` даёт `next_cursor`, вторая страница другая, курсор другого principal — `invalid_input`. В шаблоне `items.search` получает `collection_ids`. Копии demo: скрытая доска молча отброшена, пустой результат — `not_found`, `next_cursor` всегда null, курсор не привязан к principal.
7. **SC-09.** Маркерный текст в аргументах read и `propose` не попадает ни в один лог. Копия demo: `query` в строке аудита.
8. **MCC-09.** `Backend.readiness()` в шаблоне и demo, `server.py` шаблона добавляет её в `/readyz`; проверка: отказ backend → 503. Копия demo: backend всегда готов.
9. **AC-M1.1-02, «execute без токена».** Копия `sample`, которая принимает execution token без проверки подписи; ловит EX-03.
10. Каждая новая копия краснеет на точном наборе проверок, своя — среди них.

## Minor из того же отчёта, которые дёшевы

- 11: в отчёте проверки — сообщение assertion, а не кадр ExceptionGroup (`reprcrash`).
- 12: AS-06 — executor, вызывающий `execute`, должен обслуживать tenant токена (`Service.serves`), иначе 403.
- 13: MCC-08 — вызов провайдера после `dispatch` ограничен `dispatch_timeout_s` из manifest; по тайм-ауту `outcome_unknown`.
- 16: валидаторы схем создаются один раз на tool, а не на каждый вызов.

Не делаем: 14 (реэкспорты в `server.py` — их читают тесты M3), 15 (`bundle.py` — помеченный shortcut), 17 (ключ курсора на процесс — по спеке demo курсор подписан коннектором; несколько реплик — бэклог).
