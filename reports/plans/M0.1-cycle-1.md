# M0.1 cycle 1 — plan (ponytail full)

Input: owner decision 2026-11-20, `docs/implementation-plan-v1.md` (DoD-4, DoD-6, section M0.1). Base: `claude/m0-foundation` @ `6b3fe48`.

## Ready-made solutions considered (DoD-6)

| Component | Considered | Verdict |
| --- | --- | --- |
| Secret scanner (`check_secrets.py`) | **gitleaks** 8.30.1, trufflehog, detect-secrets, GitHub secret scanning / push protection | **gitleaks** (owner decision). trufflehog is verifier-centric (live checks of found credentials, needs network) and has no path-only rules; detect-secrets is a baseline tool without per-commit history scan; GitHub secret scanning does not cover `*.pem`/`.env` file names and cannot be run on fixtures in a test. |
| How gitleaks is pinned | `gitleaks/gitleaks-action` by SHA; release binary + SHA-256; `go install …@v8.30.1` | **Release binary + SHA-256** in `scripts/ci/gitleaks.sh`. The action needs a paid licence for organisation repos and cannot be called from the fixture tests; `go install` needs a Go toolchain in CI. The checksum is the one in the release's `gitleaks_8.30.1_checksums.txt`. |
| Wrapper `scripts/ci/gitleaks.sh` | call gitleaks directly in the workflow | Need one entry point that CI, `check-all.sh` and the fixture tests share, so the tests prove what CI runs. ~50 lines of shell: download+verify, `tree` (worktree of REV → `gitleaks dir`), `range` (`gitleaks git --log-opts`). No scanning logic of its own. |
| UTF-16 / binary files | gitleaks defaults | gitleaks skips binary diffs (`IsBinary`) and does not decode UTF-16. Fixed with gitleaks' own knobs: `--log-opts "--text …"` + two regex rules for UTF-16LE/BE in `.gitleaks.toml`. No own code. |
| Historical pinned blobs | gitleaks `[[allowlists]]` with `commits`; `.gitleaksignore` fingerprints | **`.gitleaksignore`** (`commit:path:rule:line`): narrower than a commit allowlist (one rule, one line). Replaces the old `(path, blob)` pairs. |
| Mutation testing of Python | **mutmut** 3.8.1, cosmic-ray, mutatest | **mutmut** (owner decision, DoD-4). Config in `pyproject.toml` (`[tool.mutmut]`), one command `scripts/ci/mutmut.sh`. |
| Mutation proof of JSON Schema (`prove_schema_guard.py`) | mutmut/cosmic-ray/Stryker (code only); hypothesis-jsonschema, schemathesis, JSONmutator, snodge (mutate/fuzz *instances*, not schemas); JSON Schema Test Suite (tests validators) | **No ready tool mutates a schema and checks that a test suite catches it** (web search 2026-11-20). `prove_schema_guard.py` stays (AC-M0.1-04). It is now itself covered by mutmut. |

## Not done, on purpose

- Empty files with a secret name (`empty.key`) are not reported: gitleaks skips empty files. They carry no secret material. Recorded as a known limitation.
- Archives (zip/gz) are not unpacked (`--max-archive-depth` stays 0), as in M0.
- Specs and acceptance criteria are not changed.
- No macOS/arm64 binary in the wrapper: CI is linux x64; a local developer can point `GITLEAKS=` at their own binary of the same version (the wrapper checks the version).
