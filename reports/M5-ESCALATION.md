# M5 — вопросы владельцу (не блокируют работу)

Это не стоп-эскалация. Работа идёт по варианту по умолчанию. Если владелец решит иначе, это `new_scope` следующего цикла.

| # | Вопрос | По умолчанию | Метка |
| --- | --- | --- | --- |
| 1 | **MC-04 для read-only `demo`.** У `demo` нет внешнего провайдера: fixtures живут в процессе, `DEMO_PROVIDER_TOKEN` — фиктивный credential. Нечего ротировать на стороне провайдера | MC-04 проверяется на credentials, которые есть в цепочке этапа B: (а) отзыв API-токена агента в ContextForge — после отзыва 401 на всех путях; (б) ротация ключа адаптера identity по `kid` у коннектора — после удаления старого `kid` его assertions отклоняются, в том числе через ContextForge (fail closed); (в) изоляция credentials по tenant'у — connection выбирается по проверенному tenant'у (SC-05, SC-03), `DEMO_PROVIDER_TOKEN` нигде не появляется (SC-09). Ротация provider credentials — с первым реальным провайдером (M11) | `pending_owner_decision` |
| 2 | **Коды ошибок ContextForge на агенте.** ContextForge v1.1.1 сам проверяет аргументы по `inputSchema` и отвечает JSON-RPC `-32603 Internal error`, а не `invalid_input` коннектора (MCC-05). Собственный тайм-аут ContextForge (`TOOL_TIMEOUT`) отдаёт текст `MCP server error` без кода | Принять как известное ограничение upstream. Лимиты соблюдаются строже: вызов до коннектора не доходит. Коннектор сам отвечает `invalid_input` (проверено напрямую). Тайм-аут коннектора (20 с, manifest) меньше `TOOL_TIMEOUT` (25 с), поэтому агент получает `temporarily_unavailable` с `retryable`. Форка нет | `pending_owner_decision` |
| 3 | **Отзыв токена агента не мгновенный.** Отзыв действует через ≤ `AUTH_CACHE_REVOCATION_TTL` (по умолчанию 30 с, минимум 5 с) — кеш в каждом worker'е. SEC-20 требует «немедленный отзыв токенов агента» | Стенд — 5 с (минимум ContextForge). Для этапа C (EX-13: блокировка за ≤ 30 с) этого достаточно. Мгновенного отзыва в v1.1.1 нет. Правка формулировки SEC-20 («≤ 5 с») — решение владельца | `pending_owner_decision` |
