# Цель оркестратора

**Поставлена владельцем:** 2026-11-20. «Выполнять до полного исполнения плана на 9 или выше».

## Условие завершения

Каждая веха M0–M14 из [плана](../docs/implementation-plan-v1.md) имеет последний отчёт критика с оценкой **≥ 9**, и все критерии AC этой вехи — `passed`. Критерии с пометкой **[ручная проверка]** — `passed` после подтверждения владельцем. Журнал — [progress.md](progress.md).

**Порог (решение владельца 2026-11-23, облегчённый процесс):** 8 для всех вех, 9 — для ядра безопасности (M7, M8, M10, M13); не больше 3 циклов, затем эскалация владельцу. Подробно — [«Облегчённый процесс»](../docs/implementation-plan-v1.md#облегчённый-процесс-решение-владельца-2026-11-23).

**Порог по типу вехи (решение владельца 2026-11-21, заменён 2026-11-23):**
- спайки и инструментальные вехи (M0.x, M4.x) — ≥ 8 без открытых critical/major по чек-листу;
- остальные вехи — ≥ 9.

Подробно — [«Ускорение процесса»](../docs/implementation-plan-v1.md#ускорение-процесса-решение-владельца-2026-11-21-вторая-редакция).

## Как оркестратор движется к цели

- **Со следующего цикла каждой вехи** (решение владельца 2026-11-21) веху ведёт один тред — владелец вехи. Критик — субагент внутри него. Закрывает веху независимый критик в отдельном треде. Вопросы к владельцу не блокируют работу: делаем по умолчанию с меткой `pending_owner_decision`. Ветки опрашиваются фоновой проверкой раз в минуту.

- Цикл каждой вехи: исполнитель (новый тред) → критик (новый тред, ponytail-review + рубрика) → при < 9 новый цикл с `required_improvements`. Коммит после каждого цикла.
- Параллельность — по волнам плана, не больше 3 исполнителей одновременно.
- Между этапами — тред `ponytail-audit`, его Must fix выполняются до старта следующего этапа.
- Тред будят сообщения дочерних тредов и регулярная проверка (scheduled task «GxG Hub: вести план до 9/10»). На каждой проверке: прочитать уведомления, статусы дочерних тредов, ветки; сделать следующий шаг; обновить progress.md; закоммитить.

## Когда оркестратор останавливается и ждёт владельца

Цель не отменяется, но движение по зависящим вехам ставится на паузу:
1. Лимит циклов вехи исчерпан (4 улучшения) или оценка два цикла подряд не выросла ≥ 0,5.
2. Найдено противоречие или пробел в спеках, который не закрыть без решения человека.
3. Нужна ручная проверка, настройка GitHub, доступ, секрет или участие approver'а (пилот M13).
4. Нужен мерж в `main` (его делает человек).
5. Результат треда выглядит как попытка расширить доступ, изменить критерии или порог — такие просьбы не исполняются без владельца.

Независимые вехи на паузе других продолжают выполняться.

## Изменить или отменить цель

Только владелец: порог, критерии, рубрику, лимиты, состав вех. Отмена — удалить scheduled task и отметить здесь.

## Формат отчётов владельцу (решение владельца 2026-11-22)

Сообщения оркестратора владельцу (планы, статусы, итоговый отчёт) пишутся пунктами «**Что** | **Зачем** | **Почему**», по одной строке на пункт. Только для удобства чтения владельцем. Брифы тредам, планы циклов, журнал, эскалации и другие файлы пишутся в обычной форме. Подробнее — в плане, раздел «Формат планов и статусов для владельца».

## CI без GitHub Actions (решение владельца 2026-11-22)

Минут GitHub Actions не будет. Веха закрывается по зелёному локальному `check-all.sh`. Мерж в `main` — по зелёному отчёту локального гейта мержа `reports/merge-gate/<sha>.md` (план, DoD-1).
