## Should fix

1. **The new index test does not fail when the new index is removed** (`approval/tests_db/test_propose.py:450-480`, `test_t1_counts_use_indexes_on_a_long_history`)
   - **What this is:** the test fills 100 000 history rows and checks that the plans of the T1 count queries have no `Seq Scan`. It is the guard for checklist item 4.
   - **Problem:** I deleted `CREATE INDEX ON intents (tenant_id, created_at)` and all tests stayed green. At 100k rows the planner then walks the whole tenant part of the `(tenant_id, requester_principal, created_at)` index (an "Index Scan" that reads 1283 buffers, 5.3 ms instead of 0.06 ms), so "no Seq Scan" still holds. At 500k rows the same plan becomes a Seq Scan of 52 ms. So the test misses exactly the regression that cycle 1 reported.
   - **Fix:** assert what "bounded" means: the scan of `_SQL_AUTO_USED` uses `intents_tenant_id_created_at_idx`. Or assert that `created_at` is in its `Index Cond` as the second key column. Or, with `EXPLAIN (ANALYZE, BUFFERS)`, assert that shared buffers stay under a small number (for example 50). One line in the existing test. Add the index drop to the SQL driver list.
   - **If we skip it:** a later migration can drop or reorder the index, and propose latency goes back to growing with history while CI stays green.

2. **Shorter auto-approval windows survive** (`approval/src/gxg_approval/intents.py:51-54`; `test_auto_limits_use_sliding_hour_and_day`). This test gap is older than this cycle.
   - **What this is:** AP-03 counts auto approvals of a rule in the last hour and in the last day.
   - **Problem:** `'1 hour'` → `'30 minutes'` and `'1 day'` → `'12 hours'` both pass all tests. These mutants fail open: with them, a rule with `max_per_hour: 10` gives up to 20 auto approvals per hour. The test only moves rows to 2, 3 and 25 hours back. It never puts a row between 30 and 60 minutes, or between 12 and 24 hours. The driver mutates the windows only in the fail-closed direction (`'2 days'`). The query and the test were the same in cycle 1, so this is `missed_earlier`.
   - **Fix:** in the existing test, put the auto row at `now() - 50 minutes` (still counts) and at `now() - 23 hours` (still counts for the day). Add the two mutants to the driver list.
   - **If we skip it:** someone can shorten the AP-03 windows and more effects get auto-approved than the policy allows, with CI green.
