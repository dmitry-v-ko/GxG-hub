## Must fix

1. **An empty `.env` or `server.pem` passes CI** (`.gitleaks-strict.toml:21-26`, `reports/plans/M0.1-cycle-1.md` "Not done, on purpose")
   - **What this is:** AC-M0-04 says CI rejects a commit with a file whose name matches the secret patterns (`*.pem`, `.env`). The file-name rule does this in gitleaks.
   - **Problem:** gitleaks only looks at file names of files that have content. `touch .env && git add -f .env && git commit` -> `tree` 0, `range` 0, CI green. The old scanner rejected it (M0). The executor knows and lists it as a known limitation, but that narrows an AC, and only the owner may change one. AC-M0.1-01 asks for "all cases of AC-M0-04".
   - **Fix:** The owner picks one: (a) accept "non-empty file" as the AC-M0-04 reading and write it into the plan; or (b) allow a name check outside gitleaks (one `git diff --name-only --diff-filter=AR … | grep -iE` line in `gitleaks.sh`, plus fixtures for empty `.env` / `server.pem`). (b) is own code, which AC-M0.1-02 forbids, so either way it is the owner's call.
   - **If we skip it:** No key leaks (the file is empty, and the commit that fills it is caught), but the milestone closes with an AC that is not met as written.

## Should fix

2. **`.env*` names other than `.env` and `.env.<x>` pass** (`.gitleaks-strict.toml:24`)
   - **What this is:** The M0.1 "Делаем" line asks for names `*.pem`/`*.key`/`*.p12`/`.env*`, any case.
   - **Problem:** The regex is `\.env(?:\.[^/]*)?`. A commit with `.envrc` containing `export DB_PASSWORD=hunter2hunter2` is green (checked), and `.env-local` too. `.envrc` (direnv) is a usual place for real secrets, and a plain password does not hit any default gitleaks rule.
   - **Fix:** `\.env[^/]*` in the path regex (keep the `.env.example` allowlist), plus fixtures `.envrc`, `.env-local`, `.ENV_PROD`. One regex and three list items. If the owner meant only `.env` and `.env.*`, say so in the plan instead.
   - **If we skip it:** Secrets in `.envrc`-style files reach the repository.

3. **The network guard is home-made, has a hole, and a mature plugin exists** (`conftest.py:26-50`)
   - **What this is:** AC-M0-01 relies on an autouse fixture that patches `socket.connect` / `connect_ex`. This cycle touched it (split for mutmut).
   - **Problem:** UDP needs no `connect`: a test doing `sendto` to `192.0.2.1:9` passes (checked). Adding `AF_INET6` to `_ALLOWED_FAMILIES` also leaves every test green, because mutmut does not mutate module-level sets. `pytest-socket` (PyPI, packaged in Debian/Fedora/Arch) blocks socket creation itself (`--disable-socket --allow-unix-socket`), so both cases fail there. The M0.1 plan's ready-made table does not list this component at all (DoD-6). By the critic template, a self-written part with a mature tool and no written reason is `major`.
   - **Fix:** Pin `pytest-socket`, add `--disable-socket --allow-unix-socket` to `addopts`, delete `_install_network_guard` / `_no_network` / `NetworkAccessError` (~30 lines), keep the two AC-M0-01 tests and add one UDP `sendto` test. Or write in the plan why the plugin does not fit.
   - **If we skip it:** A test (or a library it calls) can send data to the internet over UDP, and AC-M0-01 still looks proven.

## Nice to have

4. **The keyword tables of `schema_lock.py` are not mutation-tested** (`scripts/ci/schema_lock.py:44-62`)
   - **What this is:** `SUBSCHEMA`, `NAMED_SUBSCHEMAS`, `SUBSCHEMA_LIST` decide where `required` arrays are found and which keys are normalised. mutmut does not mutate module-level constants, so "669/669" does not cover them.
   - **Problem:** 13 single-entry removals survive (list above). Today they change nothing, because no schema has `required` under those keywords (the lock stays the same). When a schema gets `$defs/x/required`, `required_map` will miss it, and `prove_schema_guard.py` will not try to drop that field. The normative hash still catches the change, so no weakening slips through.
   - **Fix:** One test with a small schema that has `required` under each keyword and asserts the pointers `required_map` returns. About 15 lines.
   - **If we skip it:** A wrong edit of a table goes unnoticed until a schema uses that keyword.

5. **Help texts deleted to avoid mutants** (`scripts/ci/schema_lock.py:164`, `scripts/ci/prove_schema_guard.py:183`)
   - **What this is:** `--write` and `--only` lost their `help=` strings; the lock error message tells people to run `--write`.
   - **Problem:** `schema_lock.py --help` no longer says what `--write` does. The code was changed to suit the tool, not the user.
   - **Fix:** Put the `help=` strings back with `# pragma: no mutate (help text)`, as already done for `description=`.
   - **If we skip it:** Small loss of self-documentation.

6. **The secret fixture step makes every CI run 4x longer** (`tests/secrets/test_gitleaks.py`, `.github/workflows/ci.yml` job `secrets`)
   - **What this is:** 65 tests, each builds a repo and runs gitleaks 4 times (tree and range, two configs): about 260 gitleaks starts.
   - **Problem:** CI went from 33 s to 2 min 10 s per push (the fixture step is 105 s, mutmut 86 s in parallel). Fine for one maintainer, but every agent cycle waits for it.
   - **Fix:** Put all positive cases into one repo and assert every expected `File:` line in one `tree` + one `range` run; keep separate repos only for the cases that need history (added and removed, merge, zero SHA, plan quote). Same coverage, a few gitleaks starts.
   - **If we skip it:** ~100 s per CI run.

7. **mutmut config uses a deprecated key** (`pyproject.toml` `[tool.mutmut] tests_dir`)
   - **What this is / Problem:** mutmut 3.8.1 warns `tests_dir is deprecated, use pytest_add_cli_args_test_selection`. A future mutmut bump can drop it and silently change which tests run.
   - **Fix:** Move `tests/ci/ tests/contract/` into `pytest_add_cli_args_test_selection`.
   - **If we skip it:** A warning now, possible breakage on upgrade.

8. **One-line fixture that returns a module** (`tests/ci/test_schema_guard.py:34-36`)
   - **Problem:** `guard()` only returns `prove_schema_guard`; every test could use the import directly.
   - **Fix:** Delete the fixture, use the module. Lean.
