## Should fix

1. **The name check in merge commits has no test** (`scripts/ci/gitleaks.sh:79`, `-m` in `names git log ...`)
   - **What this is:** For a PR range, the name check lists the files of every commit with `git log --name-only`. `-m` makes git also list the files a merge commit brings in itself.
   - **Problem:** Nothing tests it. I removed `-m` from that line and ran `uv run pytest tests/secrets`: 19 passed, 150 subtests, all green. But the case is real: a PR whose merge commit adds an empty `.env` (`git merge --no-commit side; : > .env; git add -f .env; git commit`) is red with `-m` and green (exit 0) without it. gitleaks cannot help, the file is empty. The merge commit is one of the M0 regression cases (`test_key_in_a_merge_commit_fails`), but only for content.
   - **Fix:** One test: a merge commit that adds only an empty `.env`, `range` must be red with `gitleaks.sh: secret file name: .env`. No code change.
   - **If we skip it:** Someone drops `-m` as noise and CI stays green while empty secret-named files can enter through merge commits.

## Nice to have

2. **The name check passes when grep itself fails** (`scripts/ci/gitleaks.sh:44`, `{ grep -zP "$NAMES" || true; }`)
   - **What this is:** `|| true` is there because grep exits 1 when nothing matches.
   - **Problem:** It also hides exit 2 (grep error). With a grep that has no `-P` (BSD grep on macOS, busybox), `gitleaks.sh tree` on a repo with only an empty `.env` prints `grep: invalid option -- P` and exits 0. I checked this with a fake `grep` that fails on `-zP`: rc=0. CI uses GNU grep, so CI is not affected; the script header invites local runs "elsewhere" with `GITLEAKS=...`.
   - **Fix:** `{ grep -zP "$NAMES" || [ $? -eq 1 ]; }` — the existing `|| return 2` then turns a grep error into a failure.
   - **If we skip it:** A local check on a Mac says "clean" for an empty `.env`; CI still catches it.

3. **Any test can switch the network block off** (`pyproject.toml` addopts, pytest-socket)
   - **What this is:** pytest-socket gives tests an opt-out: `@pytest.mark.enable_socket` or the `socket_enabled` fixture.
   - **Problem:** A test with either one and a UDP `sendto` to 192.0.2.1 passes (I ran it: 2 passed). The old guard had no such switch, and the repo already forbids the comparable opt-outs for skip/xfail (DoD-5). It is visible in review, so it is not a hole by accident.
   - **Fix:** In `conftest.py`, record a violation (the existing `_record`) for any item with the `enable_socket` marker or the `socket_enabled` fixture; or write in the plan that the opt-out is accepted.
   - **If we skip it:** A network-using test can be added on purpose and CI stays green.
