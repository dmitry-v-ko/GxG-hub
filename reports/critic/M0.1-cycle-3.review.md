## Should fix

1. **The new hook hides the test of the main network switch** (`conftest.py:27-28`, `pyproject.toml:49`)
   - **What this is:** The network block for tests (AC-M0-01) comes from `--disable-socket` in `addopts`. pytest-socket applies it in the setup phase, so it also covers fixtures. The new hook calls `disable_socket()` again, without any condition, right before each test body.
   - **Problem:** The five network tests in `tests/ci/test_pytest_policy.py` open sockets in the test body, and the hook blocks those by itself. So they no longer prove that `--disable-socket` is set. Case: delete `"--disable-socket",` from `addopts` -> `uv run pytest` 106 passed, all green. In that state a fixture that sends UDP to 192.0.2.1 passes (1 passed); with the flag it errors. Before this change the same deletion turned the five tests red. Also the cycle-2 proof "with `--force-enable-socket` the 5 network tests fail" no longer holds: `pytest --force-enable-socket tests/ci/test_pytest_policy.py` -> 32 passed.
   - **Fix:** Delete the hook. Instead treat an opt-out as a DoD-style violation, like skips: in `pytest_collection_modifyitems`, `_record` every item with the `enable_socket` or `allow_hosts` marker or the `socket_enabled` fixture. Then the five network tests depend on `addopts` again, and finding 2 is closed too. Keep `test_no_per_test_network_opt_out`, but expect a red run.
   - **If we skip it:** Someone drops the flag (for example while debugging) and CI stays green; fixtures that call the network then pass unnoticed.

2. **A test can still open the network in a fixture** (`conftest.py:4-6,27-28`, `tests/ci/test_pytest_policy.py:59-73`)
   - **What this is:** The docstring and the plan say: no marker, fixture or `allow_hosts` lifts the block.
   - **Problem:** The hook runs only in the call phase. Fixtures run before it (setup) and after it (teardown). Case: a test with `@pytest.mark.enable_socket` and a fixture that sends UDP to 192.0.2.1 in setup, in teardown, or as a module-scoped fixture -> passes; the same with the `socket_enabled` fixture placed before the network fixture -> passes (probe: 5 passed, control without opt-out failed). The new test only checks the test body, so it does not see this. The conformance report names this in `known_limitations`, but the docstring and the AC-M0-01 evidence say there is no opt-out.
   - **Fix:** Same fix as 1: record the markers and the fixture at collection time. No hook needed.
   - **If we skip it:** The cycle-2 opt-out stays open for fixtures, and the docs claim more than the code does.

3. **The conformance report states a check that is no longer true** (`reports/conformance/M0.1.json`, AC-M0-01 `actual`)
   - **What this is:** The evidence for AC-M0-01.
   - **Problem:** It still says "with --force-enable-socket all 5 fail". At `91e6e09` they pass (32 passed), because of the hook.
   - **Fix:** After fix 1, rerun and write down the real result.
   - **If we skip it:** The report is not reproducible on this point.
