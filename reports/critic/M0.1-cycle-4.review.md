## Nice to have

Rated minor, as the cycle-3 opt-out gap in fixtures was: each is a gap in an extra guard, AC-M0-01 itself holds (offline run green).

1. **The `socket_enabled` fixture and pytest-socket's own switch still open the network without a red run** (`conftest.py:26-31`, `tests/ci/test_pytest_policy.py:54-83`)
   - **What this is:** The new check looks only at markers and at `item.fixturenames`, the fixture names known at collection time.
   - **Problem:** A fixture asked for at run time is not in that list, and a direct call never shows up. Probes in the clean clone, each test sends UDP to 192.0.2.1:9: `request.getfixturevalue("socket_enabled")` in the test body -> 1 passed, exit 0; the same call inside a fixture the test uses -> 1 passed; `pytest_socket.enable_socket()` in the body -> 1 passed; `socket.socket = pytest_socket._true_socket` -> 1 passed. Control without opt-out -> failed. The docstring (`conftest.py:3-6`) and the AC-M0-01 evidence in `reports/conformance/M0.1.json` say there is no per-test opt-out. The same four probes also pass at `91e6e09`, so the gap is older than this cycle; the cycle-3 review did not probe it.
   - **Fix:** Smallest honest fix: say in the docstring and in `known_limitations` that only static opt-outs are caught. Full fix: run the suite in CI with no network at the OS level (finding 2); that catches every form without more conftest code.
   - **If we skip it:** A test that needs the network can land with a green CI, and the docs claim a guarantee that the code does not give.

2. **CI never runs the suite without network, and pytest-socket does not cover import time or child processes** (`.github/workflows/ci.yml` job `tests`, step "AC-M0-01")
   - **What this is:** AC-M0-01 says `uv sync && uv run pytest` passes without network. In CI the step runs with full network; the only guard is pytest-socket, which blocks sockets in test setup, call and teardown of the pytest process.
   - **Problem:** Probes: a test module that sends UDP at import time -> 1 passed, the send went out (`IMPORT sent`); a test that starts `python -c` which sends UDP -> 1 passed. Both would fail in a really offline clone, but CI is green. The suite already runs CI scripts as subprocesses (`e2e` tests), and `scripts/ci/gitleaks.sh` downloads a binary, so a new `e2e` test that calls it would need the network unnoticed (that is why `tests/secrets` is outside `testpaths`). Only the critic checks offline, by hand.
   - **Fix:** Ready tool, no new code: after `uv sync`, run the pytest step in an empty network namespace, for example `sudo unshare --net -- sudo -u "$USER" env PATH="$PATH" uv run --offline pytest` (form on the GitHub runner not verified here; locally `unshare -rn uv run --offline pytest` -> 107 passed). Keep pytest-socket for fast local feedback.
   - **If we skip it:** AC-M0-01 stays checked only by hand; a network dependency at import or in a subprocess reaches `main` with green CI.
