Добавлены conformance-набор `check-connectors` (pytest-плагин, 19 проверок MC/SC/EX, test bundle, fake Approval Service), шаблон copier `templates/python-fastmcp` и генератор `scripts/new-connector`. `demo` переведён на кит и шаблон; 10 испорченных копий `demo` и 2 копии `sample` доказывают, что проверки краснеют.

## Must fix

1. **Гейт вехи красный: `ruff check .` падает** (`packages/gxg-connector-kit/tests/test_effects.py:69`, `:589`)
   - **What this is:** `scripts/ci/check-all.sh` — это CI вехи (DoD-1). Его второй шаг — `uv run ruff check .`.
   - **Problem:** В тестах стоят `# noqa: PLC0415`, а корневой `pyproject.toml` уже глушит PLC0415 для `**/tests/**`. Ruff считает noqa лишними (RUF100) и падает. Воспроизводится на чистом worktree `58518ce` и на `1b21413`, где отчёт исполнителя пишет «ruff check: ok».
   - **Fix:** Убрать два `# noqa: PLC0415` (`ruff check --fix`). Перезапустить весь `check-all.sh` и записать честный `ci_local`.
   - **If we skip it:** Гейт вехи красный, отчёт `ci_local` не соответствует commit'у.


2. **`scripts/ci/mutmut.sh` без второго аргумента всегда красный — а `check-all.sh` вызывает его именно так** (`scripts/ci/mutmut.sh:56`)
   - **What this is:** Скрипт сверяет выживших мутантов со списком эквивалентных, но только с теми, что «прогонялись сейчас» (`ran.txt`). Это новая строка M1.1.
   - **Problem:** `ran.txt` читается из `"$all"`, а `all` по умолчанию `/dev/null`. Без ALL_RESULTS_FILE список «прогнанных» пуст, все 27 эквивалентных считаются необъяснёнными, exit 1. Мой прогон `MUTMUT_DIRS="packages/gxg-connector-kit tools/gxg-connector-check connectors/demo" scripts/ci/mutmut.sh <report>`: `not killed: 27, listed as equivalent: 0`, `SURVIVED, not equivalent: …`. В `check-all.sh` стоит `scripts/ci/mutmut.sh >/dev/null` без аргументов. Исполнитель запускал скрипт с двумя аргументами, поэтому у него было зелено.
   - **Fix:** `sed -E 's/: .*//' "$tmp/all.txt" | sort > "$tmp/ran.txt"` (одна строка). Добавить тест в `tests/ci` (как для M0.1): запуск без второго аргумента на подставном `mutants/`.
   - **If we skip it:** Последний шаг гейта красный у любого, кто запускает `check-all.sh` как написано, — интегратор тоже.

3. **`copier update` не работает, хотя весь выбор copier стоит на нём** (`scripts/new_connector.py:60`; `copier.yml`; `.copier-answers.yml` у demo и сервиса; план «Лестница»)
   - **What this is:** DoD-6: copier выбран вместо cookiecutter, потому что «умеет `copier update`: сервисы в чужих репозиториях получают обновления шаблона». В `server.py`, `copier.yml` и README написано «`copier update` keeps this file in step».
   - **Problem:** Шаблон — подкаталог GxG-hub, а не корень git-репозитория. Поэтому в ответах нет `_commit`, а `_src_path` — абсолютный путь машины генерации (`/home/user/GxG-hub/templates/python-fastmcp`). `copier update` в сгенерированном сервисе: `Cannot update because cannot obtain old template references`. У `demo` связь с шаблоном держит только побайтный тест.
   - **Fix:** `copier.yml` в корне GxG-hub с `_subdirectory: templates/python-fastmcp/template`. Рендерить из git URL с `vcs_ref=kit_rev`: в ответах будут `_src_path: <url>`, `_commit: <rev>`. E2E-тест: сгенерировать на rev A, затем `copier update --vcs-ref B`. Либо убрать обещание `copier update` из docstring'ов и обоснования.
   - **If we skip it:** Telegram- и KB-сервисы не получат исправлений шаблона, хотя документация обещает обратное.


4. **`.dockerignore` сервиса в отдельном репозитории не исключает `.env`** (`template/{% if kit_source == "path" %}Dockerfile.dockerignore{% else %}.dockerignore{% endif %}.jinja`)
   - **What this is:** Production Dockerfile сервиса делает `COPY . .`. `.gitignore` того же шаблона ожидает локальный `.env`.

Разработчик держит `SAMPLE_PROVIDER_TOKEN` в `.env` для локального запуска и делает `docker build .` → токен попадает в слой `/app/.env` production-образа. В path-режиме allowlist `!connectors/<name>` тоже включает `.env`.
   - **Fix:** Добавить `.env`, `**/.env*`, `mutants`, `.*_cache` в обе ветки шаблона. Или перейти на allowlist (`*`, `!src`, `!pyproject.toml`, `!uv.lock`, `!gxg-manifest.yaml`, `!schemas`).
   - **If we skip it:** Credential провайдера в образе в registry (SEC-17).

## Should fix

5. **Набор доверяет счётчику и режимам, которые выдаёт сам коннектор** (`gxg_connector_check/harness.py:262,280`, `checks.py:133-147, 249, 313`)
   - **What this is:** «Ноль обращений к провайдеру» в SC-04/SC-10 и коды MC-03 проверяются через `Running.calls()` и `Harness.failures` из harness'а самого сервиса.
   - **Problem:** Нет положительного контроля. Случай 1: испорченная копия 04 (бэкенд до проверки прав) + `calls=lambda: 0` в `conformance.py` → `check-connectors` зелёный, все 11 проверок passed. Так же выглядит честная ошибка: harness считает вызовы фикстурного `Backend`, а сервис уже ходит в настоящий клиент Telegram. Случай 2: копия 08 (429 не retryable) + `failures=("crash",)` → MC-03 passed, не проверив ни одного режима.
   - **Fix:** В SC-10 после успешного вызова reader'а — `assert running.calls() > 0`. В MC-03 — `assert {"rate_limited", "temporarily_unavailable"} <= set(h.failures)`. Добавить обе поломки в испорченные копии.
   - **If we skip it:** У сервиса в чужом репозитории SC-04/SC-10/MC-03 можно незаметно выключить. Ради этих проверок набор и делался.


6. **EX-проверки не видят двух MUST из EFF-18** (`checks.py:404-458`)
   - **What this is:** EFF-18 п.1 требует локальный кеш `jti`, п.3 — что tenant, connection и resource из токена обслуживает этот коннектор (`serves()` в домене).
   - **Problem:** Случай 1: в `sample` заменить кеш `internal.tokens._jti` на «всегда новый» → EX-04 зелёный: повтор отбивает CAS fake'а (409), а `again.status_code in (401, 409)` принимает оба ответа. Случай 2: `serves()` → `return True` → все 19 проверок зелёные: нет проверки с токеном на чужой tenant или ресурс. `serves()` пишет каждый сервис сам (в ките только вызов), и тестов на неё в шаблоне нет.
   - **Fix:** В EX-04 повтор того же токена при `dispatch_status=409` должен давать 401/409 **без** второго запроса к `dispatch` (`len(env.approval.dispatch_calls) == 1`). В EX-03 добавить токен с согласованным `ahs` на ресурс или tenant, который сервис не обслуживает → 403, ноль вызовов. Две испорченные копии `sample`.
   - **If we skip it:** Сервис, который исполняет токен на чужой ресурс, проходит conformance.


7. **SC-10 и MC-02 не проверяют явный неразрешённый ресурс в поиске, пустой результат и пагинацию** (`checks.py:110-130, 298-319`; `harness.py:250-255`)
   - **What this is:** Матрица: SC-10 — «явный запрос неразрешённого ресурса → `not_found`» (GR-17), MC-02 — «пагинация, валидный пустой результат». MCC-04: пустой результат — успех.
   - **Problem:** В `Call` нет поля для «поиск по названному скрытому ресурсу» (`board_ids=["a-secret"]`, у Telegram — `chat_ids`). Три поломки `demo`, и все зелёные: (а) скрытая доска в `board_ids` тихо выкидывается, ответ пустой; (б) пустой поиск → `not_found`; (в) `next_cursor` всегда `null` при обрезанной странице.
   - **Fix:** Добавить в `Call` поля `hidden_in_list` и `empty` (аргументы с пустым результатом). Проверки: `not_found` побайтно как у missing; пустой → `isError` нет, `items == []`, `complete is True`. Проверить `next_cursor` с `limit=1`: следующая страница не пуста, чужой cursor → `invalid_input`.
   - **If we skip it:** M6 (KB) и M11.1 (Telegram-поиск по чатам) получат «зелёный» набор при нарушении GR-17 и MCC-04.


8. **SC-09 ищет только credential и identity-токены, не тексты сообщений** (`checks.py:273-295`)
   - **What this is:** SC-09: «секреты, токены, **тексты сообщений** в ответах и логах — отсутствуют» (SEC-18).
   - **Problem:** Набор не делает `propose` в SC-09 и не ищет тексты в логах. `redact()` режет только ключи `text/body/query/args`. Случай: в `sample` `message_propose` добавляет в аудит `{"msg": args["text"]}` → все 19 проверок зелёные, текст сообщения в stdout каждого propose.
   - **Fix:** В SC-09 сделать `propose` с уникальным маркером в тексте и прочитать одну заметку/элемент. Затем проверить, что маркера и тела нет в `caplog` и `capfd`.
   - **If we skip it:** Сервис пишет тексты Telegram в логи и проходит conformance.


9. **`/readyz` не учитывает backend; набор это не проверяет** (`templates/.../server.py.jinja` build, `checks.py:165-182`)
   - **What this is:** MCC-09: «для всех коннекторов: backend доступен и загружен валидный bundle».
   - **Problem:** В шаблоне readiness = `store.readiness` (+ JWKS для эффектов). Места для проверки backend нет. MCCC-09 проверяет только отсутствие bundle. Случай: KB-сервис из шаблона, Supabase недоступен → `/readyz` 200, ContextForge шлёт вызовы в мёртвый сервис. В `demo` backend в процессе, там это безвредно, а в шаблоне для настоящих сервисов — нет.
   - **Fix:** `Backend.readiness()` в шаблоне (фикстура: всегда ready, режим `temporarily_unavailable` → not ready) и `readiness_of(store.readiness, backend.readiness, …)`. В наборе: `running.fail("temporarily_unavailable")` → `/readyz` 503.
   - **If we skip it:** Требование MCC-09 не выполнено в каждом новом сервисе.


10. **Явно названный в AC-M1.1-02 класс «`execute` без токена» не имеет испорченной копии** (`tools/gxg-connector-check/tests/broken/`, `tests/toolkit/test_template.py:113`)
   - **What this is:** AC перечисляет: нет identity, ресурс до identity, вызов провайдера до проверки, **`execute` без токена**, ошибка вне envelope, неограниченный вывод.
   - **Problem:** У `demo` эффектов нет (M8 не влита — договорённость владельца). Две копии `sample`: `ex03-any-caller` (нет проверки service JWT) и `ex11`. Копии, где execution token не проверяется, нет. План обещал 3 копии `sample`, сделано 2.
   - **Fix:** Копия `sample`, где `Internal.tokens.verify` принимает любой токен (декодирует без подписи) → EX-03 красный.
   - **If we skip it:** Одна из перечисленных в AC поломок не доказана.


## Nice to have

12. **Кит не проверяет tenant'ов executor'а** (`effects.py:226-227`)
    - **What this is:** AS-06: доступ к endpoint'ам — по `kind` **и списку tenant'ов** сервиса.
    - **Problem:** `execute`/`reconcile` проверяют только `kind == "executor"`. Executor, зарегистрированный для `t-alpha`, может вызвать `execute` с токеном `t-beta`. В v1 executor один с `"*"`, поэтому сейчас вреда нет; код перенесён из M8.
    - **Fix:** После `_checked`: `claims["ten"]` ∈ tenants вызывающего (или `"*"`), иначе 403. Одна строка и один тест.
    - **If we skip it:** При разделении executor'ов по tenant'ам изоляции на коннекторе не будет.


13. **`provider.send` без тайм-аута** (`effects.py:268`)
    - **What this is:** MCC-08: конечные тайм-ауты.
    - **Problem:** Read-путь ограничен `limits.timeout_s`, а `execute` ждёт провайдера бесконечно. Executor через `dispatch_timeout_s` ставит `outcome_unknown`, а запрос в коннекторе висит дальше и держит соединение. Зависший провайдер → по висящей корутине на каждую попытку.
    - **Fix:** `asyncio.wait_for(self.provider.send(...), spec["dispatch_timeout_s"])` → `outcome_unknown` (уже ветка `except Exception`).
    - **If we skip it:** Утечка соединений при зависании провайдера.
