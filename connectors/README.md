# Доменные MCP-коннекторы (план)

Эта папка — место для **самостоятельных MCP-серверов**, а не копии инструментов внутри ContextForge. Для каждого обязательны [MCP Connector Contract v1](../docs/MCP_CONNECTOR_CONTRACT.md), conformance tests и классификация эффектов. Готовые SDK/FastMCP-шаблоны и генератор описаны в [целевом Toolkit](../docs/CONNECTOR_TOOLKIT.md), но пока не реализованы.

Планируемые адаптеры:
- `knowledge-mcp/`: семантический поиск и получение разрешённых фрагментов существующей KB.
- `telegram-mcp/`: поиск в разрешённых чатах, контекст, позже — отправка только через общий GxG Approval Service; `search` может маршрутизировать между быстрым архивом и дорогим запросом.
- `signals-mcp/`: чтение и запуск ограниченных функций существующего Signal Intelligence, при сохранении его workflow.
- `agent-delegation/` (позже): мост MCP → A2A для Hermes / специальных агентов.

Ни одного коннектора в этом начальном коммите ещё нет. Сперва проверяются готовые MCP-обёртки, потом пишется минимальный адаптер.

Важное: передавать tenant/agent identity от gateway до коннектора **только по проверенному механизму**. Параметр `agent_id` в вызове инструмента не является удостоверенной идентичностью. Без подтверждённого end-to-end механизма ресурсные действия запрещены.

Человеческое подтверждение принадлежит отдельному [Approval Service](../docs/APPROVALS.md), а не каждому коннектору. Коннектор обязан отказать в выполнении эффекта без валидного разрешения на точные параметры и без повторной проверки ресурсного доступа.
